# Prompt only for missing arguments, and only on a TTY

When stdin and stdout are both terminals, `new`, `add` and `repo rm` prompt for an argument left out (the Workspace name, the Repos, the Repo to unregister) instead of failing; anywhere else they fail with wrkt's own error, so scripts behave exactly as before. When there is nothing to choose from (no Repos registered, or every Repo already in the Workspace), that reason is reported instead, on a TTY or not, and before any prompt. Every prompt runs before any git work, and cancelling one (Esc or Ctrl-C) exits 130 with nothing done. We chose this over a Workspace picker for `status`, `sync`, `push` and `rm` outside a Workspace, over turning `rm`'s refusal into a "remove anyway?" confirmation (which would weaken the safety guarantees in the README), and over a `--no-input` flag, which TTY detection makes redundant. The trade-off: a single argument to `add` that is not a registered Repo but names an existing Workspace is now read as that Workspace's name, so a Repo and a Workspace sharing a name resolve to the Repo.
